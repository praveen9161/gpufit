# Plan: GPUFit v0.1, an installable tool (validated in session C)

Status: **implemented in v0.1.0**, validated on 4x A10G in session C (2026-10-02).

Goal: a platform team can install GPUFit on its GPU cluster with one command, first **watch**
what it would do and what it would save, then let it **act**, including rescuing training jobs
already running on a GPU that degrades. Session C proves that flow on 4 real A10Gs.

## What a user does

```bash
helm install gpufit oci://ghcr.io/praveen9161/charts/gpufit \
  --namespace gpufit --create-namespace \
  --set mode=observe --set pricePerGpuHour=2.50     # driver defaults to gpu.nvidia.com

kubectl gpufit status                 # GPUs, scores per workload, pools, what GPUFit would do
kubectl gpufit report --since 24h     # training GPU-hours on degraded GPUs, estimated waste and $ saved
kubectl gpufit why <pod>              # why a GPU pod is Pending

helm upgrade gpufit ... --set mode=enforce          # start acting: degraded GPUs -> inference pool
helm upgrade gpufit ... --set rescue.enabled=true   # also move running training jobs off degraded GPUs
```

## Modes

| Mode | Scores | Taints / pools | Restarts running jobs | Report |
|---|---|---|---|---|
| `observe` (default) | yes | no: logs and events say what it *would* do | no | yes |
| `enforce` | yes | yes | no | yes |
| `enforce` + `rescue.enabled` | yes | yes | yes, after a grace period, only jobs that opted in | yes |

Observe-only is the default so a team can trial it without risk; it also measures the number
the savings depend on (how often their GPUs are degraded) on their own fleet.

## Pieces

- **Helm chart**: agent DaemonSet, controller Deployment, RBAC, config (thresholds, hysteresis,
  mode, price, collector). Published to GitHub's container registry (free for public repos).
- **Images and binaries**: built and published by GitHub Actions on each release tag (agent +
  controller image for amd64/arm64; `kubectl-gpufit` binaries for macOS/Linux).
- **Workload type**: from a pod/claim label `gpufit.io/workload: training|finetune|inference`
  (`gpufit-claim` already sets it on claims). Unlabelled GPU work is treated as inference.
- **Report**: the controller tracks which training pods hold GPUs whose training score is below
  the threshold, and for how long. Estimated waste = GPU-hours x job size x estimated slowdown.
  The slowdown estimate is shown as an estimate, with the measured values from sessions A2/B
  as reference; v1's scores overstate small degradations (session B: score 50, real loss 16%).
- **Rescue**: for an opted-in training job (label `gpufit.io/rescue: "true"`) whose GPU leaves
  the training pool and stays out for the grace period: ask the job to checkpoint (signal),
  delete its pods, and let Kubernetes recreate them; they land on training-pool GPUs and resume
  from the checkpoint. Workloads must support checkpoint/resume (`train_ddp.py` will).
- **Metrics** (Prometheus): scores per GPU and workload, pool per node, degraded GPU-hours,
  estimated waste and savings, rescues and how long each took. A Grafana dashboard JSON in the repo.
- **Collector**: `nvidia-smi` (done). DCGM is the next collector, not in v0.1.

## Session C: validate v0.1 on real GPUs

4x g5.xlarge (A10G), k3s + NVIDIA DRA driver, GPUFit installed **with the Helm chart**.
1. Observe mode: 2-GPU training on A+B, inference on C, D free. Degrade B mid-job. GPUFit only
   reports. `kubectl gpufit report` shows the estimated waste.
2. Same job, enforce + rescue: degrade B mid-job. GPUFit moves B to the inference pool,
   checkpoints and restarts the job on A+D, B serves inference.
3. Measured: time to finish the job in both runs, GPU-hours, $, how long detection and the
   rescue took, inference throughput on B, and how the report's estimate compares with the
   measured waste.
Rehearsed on kind first (CPU), as for session B. **Cost: 4 x ~$1/h, about 1.5 h ~ $6-8.**

## Not in v0.1

DCGM collector, active probe, NVLink/network health, Kueue integration, multi-cluster, a web UI.
They stay on the roadmap.
